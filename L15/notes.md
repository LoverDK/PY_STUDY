# L15 复杂度估题专项：循环嵌套与均摊直觉

阶段：A — DSBA / Python / 可视化 / 复杂度。仓库路径：L15/。
范围：循环次数求和、重置与单调指针、几何级数、均摊成本直觉、显式操作计数。
不讲：完整滑动窗口/单调栈专项、势能法形式化证明、具体解释器扩容公式、计算机系统原理。

## 目标与模型
能按“定义规模→确定核心操作→检查状态是否重置→写求和/总量上界→报告时间和空间”估题。采用固定大小数值的常数成本模型；任意大整数的位复杂度另论。Θ 表示紧确增长阶，O 表示渐近上界。计数器只统计声明的操作，不代表全部指令或运行秒数。

## 第一段：嵌套循环要把每层次数写成总和
是什么：总工作量是所有外层取值对应的内层工作量之和，不是见到缩进就机械相乘。
为什么：内层次数可能固定、随 i 增长、随 i 减少，或由共享状态限制。
怎么写：
```python
for i in range(n):
    for j in range(i + 1):
        work()
```
核心操作次数是 1+2+...+n=n(n+1)/2，故 Θ(n²)。若内层改成 range(3)，是 3n，Θ(n)；若内层遍历独立长度 m 的列表，是 nm，Θ(nm)，不能无依据写 n²。
顺序执行的两个循环相加；嵌套且内层每轮完整执行才乘相应次数。检查空输入时公式也应返回 0。
易错点：①少执行一半仍是二次增长；②将独立的 n、m 偷换成同一规模；③忽略 work() 本身可能是切片、搜索等非恒定操作。
何时用：笔试读代码、枚举位置对、预测输入规模允许的循环方案。

## 第二段：共享单调指针，内层未必重复 n 次
是什么：一个指针从起点出发，跨外层迭代保留位置且不回退，其总移动次数受可走距离限制。
为什么：错误的“n 次外层×内层最坏 n 次”重复计入了不可能反复发生的移动。
怎么写：对整数列表（无需排序），依次处理索引 i，并将 j 推到至少 i+1：
```python
j = 0
for i in range(n):
    while j <= i:
        j += 1
```
第 i 轮开始时 j=i，故每轮只移动一次，总共 n 次。更一般的共享指针程序要证明 j 有界、单调、内层每轮成本有界；不能仅看见“不重置”就自动宣布线性。
与之对照：
```python
for i in range(n):
    j = 0
    while j <= i:
        j += 1
```
现在移动总数为 n(n+1)/2。关键不是两层语法，而是 j 是否在外层内重置。
只数成功移动还不够：第一段共享版本 while 条件对每个 i 有一次成功、一次失败，共 2n 次；外层开销也是线性，因此总时间 Θ(n)。
易错点：①把 j=0 放错层，实际算法已改变；②漏数失败条件检查；③指针虽然单调，但循环体含线性搜索，整体仍可能更贵。
何时用：后续双指针、窗口和批量扫描的复杂度证明。此处只学计数，不提前讲完整算法。

## 第三段：对数层数与每层工作量必须同时看
是什么：每轮规模翻倍/减半通常带来对数层数，但总成本还取决于每层做多少工作。
怎么写：
```python
width = 1
while width < n:
    for _ in range(width):
        work()
    width *= 2
```
n≥2 时 width 为 1,2,4,...,2^(k-1)，其中 k=ceil(log2 n)。总次数 2^k-1。由于 n≤2^k<2n，故总工作 Θ(n)，并非 Θ(n log n)。
若每层都执行 n 次 work，则总数 nk，才是 Θ(n log n)。若每层只执行一次，则 Θ(log n)。n=0 或 1 时上述 width<n 循环不进入，成本按边界单独说明。
易错点：①看到对数层数就忽略各层宽度；②用“最大一层×层数”作上界后，误当紧确阶；③非 2 的幂时忘记终止条件，例如 n=5 的工作量为 1+2+4=7。
何时用：分批处理、按倍增规模执行任务、理解扩容复制总量和后续分治层次。

## 第四段：均摊是整段序列的保证，不是随机平均
是什么：均摊分析把一串操作的总成本分摊到各次操作。即使某一次很贵，若整段 m 次总成本 O(m)，就可说均摊每次 O(1)。
为什么：只用“最坏一次×操作次数”可能过度估计；昂贵事件之间通常隔着许多便宜事件。
使用明确的教学扩容模型：初始容量 1，空表；每次追加写入成本 1；满时容量翻倍，并复制现有全部元素，每复制一个成本 1。忽略分配等其他代价。m 次追加的写入量是 m，复制量为 1+2+4+...（只包括实际触发的扩容）。m>0 时复制总数<2m，因此总成本<3m；从至少 m 次写入又知总成本 Θ(m)，均摊每次 Θ(1)。单次触发扩容仍可能 Θ(m)。
这只是可复现的模型，不声称 Python list 严格按 1、2、4 扩容，也不把均摊保证等同单次延迟保证。
易错点：①均摊不要求输入随机，和概率平均不是一回事；②说均摊 O(1) 就宣称每次 O(1)；③把每次只增长 1 容量也套用几何级数，其复制总量反而是 1+...+(m-1)，Θ(m²)。
何时用：理解动态容器、批量操作和偶发昂贵步骤；对延迟敏感的场景还要关注单次最坏成本。

## 第五段：用可执行计数核对，空间另算
是什么：在真正发生的核心动作处加计数器，检查小规模结果是否符合推导；计数检查辅助证明，不替代证明。
怎么写：examples.py 对三角访问、重置/共享指针、倍增分批和扩容模型分别计数，且核对 n=0、1、非 2 的幂以及多组规模。扩容模型通过位置索引枚举真实复制事件，不实际存储业务元素；模型模拟器自身只保存几个整数，额外空间 O(1)。被模拟的动态数组为了存储 m 个元素需 Θ(m) 容量。必须区分“计数模拟程序”与“所分析数据结构”。
实际算法还需把输出、临时容器、调用栈算清楚。只计数所有位置对不保存时可以 O(1) 额外空间；保存全部对则是 Θ(n²)。生成器若后面被 list() 物化，输出空间也不能忽略。
易错点：①直接返回公式伪装真实计数；②只验证 n=2 的幂，漏掉边界；③将计数器自身成本当作原程序全部成本；④把输出大小和辅助空间混为一谈。
何时用：机试复杂度说明、代码审查、对照理论与实现。报告模板：“规模是……；核心动作……次；因此时间……；额外空间……；单次最坏和均摊分别是……”。

## 综合例题
当 n=5：三角访问为 15 次；每轮重置指针移动 15 次，共享指针仅移动 5 次；倍增分批工作为 1+2+4=7 次。
连续追加 m=5 次：写入 5、复制 1+2+4=7、总成本 12，最昂贵一次为复制 4 加写入 1，共 5。整体总成本线性，单次成本可以线性；二者不矛盾。
