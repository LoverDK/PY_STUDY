# L14 算法复杂度入门：大 O 与常见对照

阶段：A — DSBA / Python / 可视化 / 复杂度  
仓库路径：L14/  
范围：输入规模、基本操作计数、大 O/Θ 的区别、常见增长级别、最坏情况、额外空间。

## 学习目标

1. 先定义 n 和被计数操作，再分析增长。
2. 从循环次数得到 O(1)、O(log n)、O(n)、O(n log n)、O(n²)。
3. 区分渐近上界、紧确增长级别和实际秒数。
4. 分别报告时间和额外空间，明确输入/输出是否计入。
5. 用小规模精确计数检查推导，而非用一次计时证明复杂度。

## 第一段：复杂度描述什么，为什么不用秒数替代

复杂度描述输入规模增长时，程序消耗如何增长。设 n 为列表元素个数，T(n) 为某类基本操作执行次数。以下讨论采用常见教学模型：定长数值的比较、加法、索引视为常数时间；Python 任意大整数、长字符串比较等若随位数增长，需要另引入位数/字符串长度参数，不能无条件视为 O(1)。

例如求非负小整数列表的最大值（非空），第一次取值后扫描剩余元素，值比较恰好 n-1 次，时间 Θ(n)，额外空间 Θ(1)。空列表约定返回 None。Python 运行开销、硬件、缓存、数据分布会影响秒数，却不改变这个模型下线性扫描的增长级别。

怎么分析：写出输入规模 → 选基本操作 → 数次数 → 化简 → 标注分析情形和模型。不要省略第一步；二维表应可能使用行数 r、列数 c，而不是把所有尺寸混称 n。

易错点：
- 一次运行快不代表增长慢；100n 与 n² 在小 n 时可能前者更慢。
- 一行代码不等于 O(1)：sum(values) 仍要访问各元素。
- 复杂度不要求精确预测秒数，不能说 O(n) 就是 n 秒。

何时用：做题前判断输入量能否承受、比较实现方案、定位大规模数据的瓶颈。

## 第二段：大 O 是上界，紧确阶让比较更有用

正式地，T(n)=O(g(n)) 意味着存在常数 C>0 和 n0，使所有 n≥n0 都有 T(n)≤C·g(n)（考虑非负代价）。它描述渐近上界。Θ(g(n)) 同时给出同阶的渐近上界和下界，表示紧确增长级别。

若 T(n)=3n²+5n+7，则 Θ(n²)，当然也属于 O(n²)，甚至 O(n³)。日常说“复杂度 O(n²)”通常希望表达有用的紧上界，但严格的 O 本身不承诺紧确。常数因子和低阶项在渐近分类时省略，并不意味着实际性能里它们不重要。

常见级别（n≥2）：

| 级别 | n 翻倍时主导量变化 | 典型结构 |
|---|---|---|
| O(1) | 基本不变 | 一次有效下标访问 |
| O(log n) | 增加一个常数量级 | 状态每轮减半 |
| O(n) | 约 2 倍 | 一次完整扫描 |
| O(n log n) | 略大于 2 倍 | n 次操作，每次至多对数轮 |
| O(n²) | 约 4 倍 | 两个各执行 n 次的嵌套循环 |
| O(2ⁿ) | 极快增加 | 枚举 n 个元素的全部子集，仅论数量 |
| O(n!) | 更快增加 | 枚举排列，仅论数量 |

不同固定底数的对数只差常数因子，故渐近分类通常写 log n；精确轮数时必须明确底数。

易错点：
- O(n²) 不代表每个输入恰好执行 n² 次。
- 把 O 当成等式代数随意消去，忽略它是函数集合的上界记号。
- n、m 独立时把 O(n+m) 强行写 O(n)；只有明确 m 受 n 控制才可合并。

何时用：读题解、解释方案能否扩展、书写有边界条件的算法报告。

## 第三段：从循环结构数次数，先保留精确表达式

顺序执行的循环相加：
```python
for x in a:       # n 次
    ...
for y in b:       # m 次
    ...
```
总计 Θ(n+m)，不是 Θ(nm)。

嵌套且内层每次完整执行：
```python
for i in range(n):
    for j in range(n):
        ...
```
内层体执行 n² 次，Θ(n²)。

三角循环：
```python
for i in range(n):
    for j in range(i + 1, n):
        ...
```
总次数 (n-1)+(n-2)+...+1=n(n-1)/2，仍为 Θ(n²)，并非“少一半所以 O(n)”。

对数循环：
```python
while n > 1:
    n //= 2
```
对整数 n≥1，循环恰好 floor(log2(n)) 次；n=0 时为 0 次。每次缩小固定比例才产生对数增长。若每轮只减 2，仍是线性。

例：n=8 时依次 8→4→2→1，执行 3 轮；n=9 是 9→4→2→1，也是 3 轮。n=8、16、32 分别为 3、4、5 轮。

易错点：
- 看到两层循环就认定平方：内层次数可能依赖 i，甚至总和仅线性；必须求和。
- 将循环变量乘 2 误认为指数时间：它到达 n 只需对数轮。
- break 让最好情况提前结束，不代表最坏情况变成常数。

何时用：阅读循环代码、估算暴力方案、比较线性扫描与缩小范围的过程。更复杂的嵌套与均摊留到 L15。

## 第四段：时间和空间分开，隐藏工作也要算

额外空间指算法运行中除输入之外新增并同时存活的空间；本课额外空间包含新建输出容器，并同时说明是否可以排除输出后报告辅助空间。

累计求和仅保留 total，是 Θ(1) 额外空间；创建长度 n 的前缀和结果，是 Θ(n) 额外空间。若把输出空间排除，其辅助空间可以为 Θ(1)，必须明确口径，不能只写“空间 O(1)”而藏掉结果列表。

输入切片 values[:] 会复制列表引用，时间 Θ(n)、额外空间 Θ(n)；并非深复制所有嵌套对象。Python 列表的按下标读取在本课模型为 O(1)，但 x in values 最坏需要 Θ(n) 次比较；集合查询的平均/期望表现不能当作任意输入下严格最坏 O(1) 的保证。

生成器也不自动令整个程序空间常数：若马上 list(generator)，仍物化 n 个输出。递归调用栈亦占额外空间，此处只建立意识，不展开递归专项。

易错点：
- 只数显式循环，漏掉切片、复制、sum 或成员搜索。
- 只看最终返回一个数，忽略中途创建的长度 n 临时列表。
- 把累计分配过的总量直接当峰值同时存活量；空间通常关注峰值。

何时用：分析 Pandas/NumPy 转换副本、处理大文件、避免循环内反复复制和内存不足。

## 第五段：情况、计数与验证形成闭环

同一函数会随输入内容改变耗时。线性查找的最好情况是第一个元素命中（Θ(1)）；最坏是末尾命中或不存在（Θ(n)）。平均情况必须指定输入分布，不能凭感觉等同最坏。一般报告应明确“最坏情况”或题目所需口径。

验证分两层：
1. 正确性：返回值是否符合规格，包括空输入、边界、重复值。
2. 分析核对：给基本操作加计数器，检查计数是否匹配公式。例如三角比较 n(n-1)/2；重复减半的轮数等于 n.bit_length()-1（正整数）。

计数器用于教学：我们记录“核心比较次数”，不是声称已经统计每条 Python 指令。计时实验可以发现常数与实现差异，但有限规模不能证明渐近复杂度。若计时，需固定任务、重复多次、说明环境和输入；本课不把噪声秒数作为硬验收。

易错点：
- 只测成功查找，漏掉最坏的不存在输入。
- 只用 n=1、2，区分不出线性、平方等增长。
- 根据运行时间翻倍就断言 Θ(n)，忽略噪声与规模范围。
- 为符合公式硬编码操作次数，而非在真实执行位置累加。

何时用：写机试分析、审阅实现、建立“代码—次数—增长—边界”的自证链路。

## 综合例题：同一批数据的三种工作

给列表 [4, 1, 7, 3]：
- 顺序求最大值：最大值 7，值比较 3 次，Θ(n) 时间、Θ(1) 额外空间。
- 枚举 i<j 的所有位置对：6 对，Θ(n²) 时间；仅计数用 Θ(1) 额外空间，若保存所有对则 Θ(n²) 空间。
- 将规模 4 不断整除 2 直到≤1：2 轮，Θ(log n) 时间、Θ(1) 空间（n≥2）。
