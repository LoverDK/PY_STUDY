## 第一段：评估在回答什么——测的是泛化，不是背题速度

监督学习真正关心的是：模型遇到**同类但未参与训练的新样本**时还能否工作。训练集既用于选择参数，又用来打分，会产生乐观偏差：模型可能记住训练数据的偶然噪声。测试集扮演一次“封卷考试”，只能在训练完成后用于最终检查。

设未知的数据分布为 (P(X,Y))，分类器为 (f)，0-1 损失为
[
L(f(x),y)=mathbf{1}[f(x)
e y].
]
理想目标是未知分布上的风险
[
R(f)=mathbb{E}_{(X,Y)sim P}[L(f(X),Y)].
]
我们无法枚举未来，只能用未参与训练的测试样本近似：
[
widehat R_{test}(f)=rac1msum_{i=1}^{m}mathbf{1}[f(x_i)
e y_i].
]
这里 (m) 是测试样本数。准确率等于 (1-widehat R_{test})。这个估计依赖一个关键假设：训练、测试与未来数据的产生机制足够接近。时间漂移、采集渠道改变、标签口径改变时，即使代码无误，测试分数也可能高估上线表现。

**什么时候用**：所有监督学习实验都要在建模前先写清评估协议。  
**具体易错点**：
- 先看完整数据的均值、缺失率或目标编码，再切分；这些统计量已经把测试信息带回训练过程。
- 反复根据测试分数选模型或阈值；测试集就逐渐变成了训练反馈，失去“未见数据”意义。
- 同一个人、设备或订单的多条记录被随机拆到两边；模型可能靠身份线索“认人”，分数虚高。此时应按组或时间划分，而不是普通随机划分。

## 第二段：怎样划分——成对、随机、分层，并守住泄漏边界

本课合成数据 (X) 形状为 ((200,4))：200 行样本、每行 4 个特征；(y) 形状为 ((200,))，其中正类约占 20%。调用：

```python
X_train, X_test, y_train, y_test, id_train, id_test = train_test_split(
    X, y, ids,
    test_size=0.25,
    random_state=42,
    stratify=y,
)
```

逐项解释：
- 同时传入 (X,y,ids)，函数用同一批索引切它们，保证第 i 行特征、标签和编号不会错位；
- `test_size=0.25` 得到 150 条训练样本和 50 条测试样本；
- `random_state=42` 固定伪随机划分，便于复现实验；42 没有特殊统计含义；
- `stratify=y` 让两边的类别比例尽量接近总体。本例总体、训练、测试正类比例实测均为 0.200。

分层不能凭空创造样本。若某类只有 1 条，既要训练集包含它又要测试集包含它是不可能的，函数应报错而不是偷偷复制。时间序列也通常不能随机打乱未来与过去。

正确顺序是：**先切分；只在训练集上 fit 预处理器和模型；把已拟合的变换用于测试集；最后预测和评分。** 本课没有缩放步骤，L66 会用 Pipeline 系统处理。  
边界验收：训练/测试 ID 集合互不相交，二者并集恰好是 0…199；形状分别是 ((150,4))、((50,4))。

## 第三段：混淆矩阵——先逐条归档，再谈公式

把 1 约定为“正类”，0 为“负类”。“正/负”只是本次关注对象的编码，不代表好坏。

|真实值|预测值|名称|含义|
|---:|---:|---|---|
|1|1|TP|真正类：该抓到的抓到了|
|0|1|FP|假正类：误报|
|1|0|FN|假负类：漏报|
|0|0|TN|真负类：正确排除|

例题：
`y_true=[1,0,1,1,0,0,1,0]`，`y_pred=[1,1,1,0,0,0,1,0]`。逐条演练如下，括号状态固定写成 ((TN,FP,FN,TP))。

|i|真实|预测|落桶|更新后的状态|原因|
|---:|---:|---:|---|---|---|
|0|1|1|TP|(0,0,0,1)|正类且报正|
|1|0|1|FP|(0,1,0,1)|负类被误报|
|2|1|1|TP|(0,1,0,2)|第二个真正类|
|3|1|0|FN|(0,1,1,2)|正类被漏掉|
|4|0|0|TN|(1,1,1,2)|正确排除|
|5|0|0|TN|(2,1,1,2)|正确排除|
|6|1|1|TP|(2,1,1,3)|第三个真正类|
|7|0|0|TN|(3,1,1,3)|第三个真负类|

最终 (TN=3,FP=1,FN=1,TP=3)。sklearn 的二分类矩阵在 `labels=[0,1]` 时按“行是真实、列是预测”排列：
[
egin{bmatrix}TN&FP\\FN&TPend{bmatrix}
=
egin{bmatrix}3&1\\1&3end{bmatrix}.
]
有些资料会交换坐标轴，所以读矩阵前必须先看定义。

手写实现的循环不变量是：处理完前 k 条后，四个计数恰好分别等于前 k 条中四种组合的数量。每条样本只会命中互斥的一个分支，因此不重不漏；循环处理完 n 条即结束，时间 (O(n))，计数器辅助空间 (O(1))，若保存每轮 trace 则另需 (O(n))。

## 第四段：四个指标分别在问什么

用 (N=TP+TN+FP+FN)。

[
Accuracy=rac{TP+TN}{N}
]
准确率问“所有判断里答对多少”。例题为 ((3+3)/8=0.75)。

[
Precision=rac{TP}{TP+FP}
]
精确率问“模型报为正的样本里，真有多少”。例题 (3/(3+1)=0.75)。误报成本高时更关注它，如人工复核资源很贵。

[
Recall=rac{TP}{TP+FN}
]
召回率问“真实正类里，抓到了多少”。例题 (3/(3+1)=0.75)。漏报成本高时更关注它。

[
F1=rac{2PR}{P+R}=rac{2TP}{2TP+FP+FN}.
]
F1 是精确率与召回率的调和平均；只有两者都高才会高。例题也是 0.75。它没有 TN，因此不适合所有业务，也不能替代成本分析。

**准确率陷阱**：测试集 50 条，其中 40 负、10 正；永远预测 0 的多数类基线得到 (TN=40,FN=10)，准确率 (40/50=0.80)，但 precision、recall、F1 全为 0。它一个正类也没抓住。由此可见“80% 准确率”脱离类别比例和混淆矩阵没有足够信息。

当 (TP+FP=0) 时模型从未报正，precision 的分母为 0；当测试集中根本没有正类时 recall 分母为 0。本课代码明确采用 `zero_division=0`，将不可计算情形记 0，同时要求报告支持数和矩阵，不能悄悄隐藏原因。

具体易错点：
1. 把 FP 与 FN 记反。记住 FP 的第一个词指**预测为正**但预测错了；FN 是预测为负却错了。
2. 换了正类编码却照搬解释。反欺诈把“欺诈=1”和“正常=1”会交换关注对象。
3. 只报 F1，不报类别比例、混淆矩阵和业务代价。
4. 用硬预测标签研究阈值变化；阈值分析应保留概率或分数，L74再系统讲。

## 第五段：完整代码工作流——基线、模型、预测、评估各司其职

`examples.py` 使用 `make_classification` 生成固定的 200×4 合成数据，无下载。它比较：
- `DummyClassifier(strategy="most_frequent")`：只学训练集中最多的类别，是“模型至少应超过什么”的基线；
- `DecisionTreeClassifier(max_depth=3)`：浅树仅作为预测器，`max_depth` 限制层数，`random_state` 固定可复现性。树如何选切分留到 L68。

`fit(X_train,y_train)` 只读取训练集并更新模型状态；`predict(X_test)` 在参数冻结后输出 50 个标签；指标函数读取 `y_test` 与预测，不修改模型。实测：
- 多数类基线：矩阵 ([[40,0],[10,0]])，accuracy=0.80，recall=0；
- 深度3树：矩阵 ([[39,1],[4,6]])，accuracy=0.90，precision≈0.857，recall=0.600，F1≈0.706。

这不是在证明浅树永远好；只证明在**这次固定合成数据和固定切分**上，它比多数类基线多捕获了 6 个正类，同时产生 1 个误报。训练模型的目标函数和树内部算法并非本课重点，本课目标是建立可信评估链。

使用建议：准确率适合类别相对均衡且两类错误成本接近；precision 适合误报贵；recall 适合漏报贵；F1 适合需要一个数平衡 precision/recall，但仍应同时展示四格计数。最终指标必须从业务损失与决策后果出发。
