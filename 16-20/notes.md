## 一、读洗筛汇：用业务规则决定顺序
是什么：把输入表转换成可验证的统计结果。为什么：重复订单、空白字符、非法数值都可能让收入报表错误，能运行不等于口径正确。
怎么写：read_csv先保留标识符文本；str.strip标准化；空串变缺失；按业务键保留最后记录；再to_numeric并验证正整数数量和有限非负价格；最后筛paid并按地区agg。完整案例使用订单编号、地区、金额、状态，演示同样的顺序。
```python
df = raw.copy()
df["order_id"] = df["order_id"].str.strip()
df = df.drop_duplicates("order_id", keep="last")
df["amount"] = pd.to_numeric(df["amount"], errors="coerce")
paid = df.loc[df["status"].eq("paid") & df["amount"].notna()].copy()
```
上面仅示意顺序；完整实现还检查缺键、非负与有限值。
易错点：①先删掉最新非法行再去重，会复活旧记录；②count只数非缺失而size数行；③一行一明细时行数不是订单数；④函数内修改输入。
何时用：机试表格题、运营汇总、CSV分析。验收同时看明细、分组、顺序和总额。

## 二、可视化：先确定比较问题，再写绘图指令
是什么：用图表达关系。地区收入比较用柱状图；按时间的趋势用折线图；两个数值变量关系用散点图；分布用直方图。
为什么：图型选错、单位缺失或顺序错误，即使代码画得出来也难以解释。
怎么写：
```python
fig = Figure(figsize=(6, 4))
ax = fig.subplots()
ax.bar(summary["region"], summary["revenue"])
ax.set(title="Paid revenue by region", xlabel="Region", ylabel="Revenue (CNY)")
ax.set_ylim(bottom=0)
fig.tight_layout()
```
柱高必须来自聚合后的同一张表，不能地区来自一套排序而收入来自另一套。柱状图用0基线帮助比较长度。读图时先看标题、单位、坐标范围和样本，再说差异；散点相关不证明因果，直方图高度也须先辨清计数/密度。
易错点：①未排序的日期被当类别导致折线顺序错；②截断柱图纵轴夸大差异；③把直方图区间当离散类别；④缺单位。
何时用：机试作图指令、图表审阅和报告。本课examples.py只输出图表数据，不写图片；上述是可选绘图片段，不声称已生成图像。

## 三、容器与推导式：选择结构并避免共享修改
是什么：list保存顺序，dict按键映射，set保存唯一成员，tuple表达固定结构。推导式是生成结果的简洁方式，不替代算法设计。
为什么：数据结构的语义决定重复、顺序和查找；可变对象别名能让正确公式也得到错误结果。
怎么写：
```python
rows = [[0] * 3 for _ in range(2)]
by_region = {row["region"]: row["revenue"] for row in records}
positive = [x for x in values if x > 0]
```
独立行用逐次创建；dict遇到重复键会覆盖，不能用它无声替代分组求和。列表成员判断通常需扫描；set/dict平均查找表现不能当任意输入的严格最坏常数。
易错点：①[[0]*3]*2共享行；②边遍历列表边删除漏元素；③用set去重后丢失要求的顺序；④嵌套推导式隐藏二次工作。
何时用：准备输入、组织分组结果、筛选映射。复杂条件优先清晰的循环和命名函数。

## 四、函数与异常：定义契约，区分无效与空结果
是什么：函数约定输入、输出和失败方式。正常的“没有符合条件记录”返回规定结构的空表；缺必需列等输入无效则抛异常。
为什么：裸except吞掉所有错误后返回0，会把程序缺陷误当真实业务结果。
怎么写：
```python
def parse_nonnegative(text):
    value = float(text)
    if not math.isfinite(value) or value < 0:
        raise ValueError("需要有限非负数")
    return value
```
转换失败原本就抛ValueError；只在明确能够处理时捕获具体异常。函数不使用[]作为可变默认参数，需默认集合时用None再创建。数据清洗函数copy，调用者保留原输入以便审计。
易错点：①except Exception后pass掩盖错误；②finally中的return覆盖原返回或异常；③默认列表跨调用共享；④把缺列当空业务结果。
何时用：可复用程序、机试接口和数据校验。

## 五、阶段收尾：用正确性、复杂度和可复核输出一起过关
是什么：不只会调用API，还应解释每一步口径和代价。
怎么验收：输入不变；键唯一；精确筛选名单；分组收入和明细总额一致；同分次排序明确；空表有固定列；异常能定位无效输入；需要作图时标签和数据对齐。
复杂度：一次扫描是线性，排序通常按比较排序模型O(n log n)，嵌套循环要数总操作；均摊与单次最坏分开。推导式不天然快一个复杂度等级；DataFrame副本与结果表也占空间。
易错点：①只验总额而不验地区对应；②只测正常数据；③用一次计时证明渐近阶；④把代码短等同复杂度低。
何时用：转入DSA之前建立统一做题流程：读约束→选结构→写算法→列边界→验证→分析时间空间。
